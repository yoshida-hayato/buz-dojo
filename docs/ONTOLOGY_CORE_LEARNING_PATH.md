## 初学者チェック（ウサギ視点・要約）

基礎の現状:
- モジュール11本・ランダム／フィルタ前提（先頭に属性から判断への薄いモジュール）
- 出題はシナリオ・正誤の**設計判断**寄り（定義暗記ではない）
- 「用語の地図」でも、データ／情報／意味／外延など一段上の語が続く

入門の現状:
- 章順教科書（導入→なぜ型→クラス→属性→関係→制約）
- 「オントロジーとは何か」から入れる

判定:
1. 基礎だけを初見で全モジュールランダムに解く → **理解が遅い／挫折しやすい**
2. 入門クリア（または同等の前提）のあと基礎へ → **理解が早い**
3. 基礎をいきなり教科書ロック全面化 → 有料本命の「判断力」役割を崩すので**今はやらない**

---

## 役割分担

| 科目 | 役割 | 学び方 |
|---|---|---|
| オントロジー入門（無料） | 型の入口・語の地図 | 章順教科書。クリアしてから基礎へ |
| オントロジー基礎（有料） | 設計判断・取り違え防止 | おすすめ学び順でモジュールを進める。全問ランダムは慣れてから |

やらないこと:
- 入門をスキップさせる売り方
- 基礎に「最新保証」「深度トラック」「属性ブリッジ」等の造語
- 問題データをビジネス道場本体へコピー（学習道場マスタのみ）
- 本正本だけで Hosting／価格変更

## 入門章 ↔ 基礎モジュール対応

（2026-09-14 キツネ事実確認: 入門6章・基礎 modules キーと一致）

| 入門（章） | 基礎で厚くなるモジュール | メモ |
|---|---|---|
| オントロジーとは／なぜ型で置くか | 用語の地図／オントロジーの定義 | 入口の語を共有してから判断へ |
| クラスとインスタンス | クラス・個体 | 基礎は境界・複数型など判断が厚い |
| 属性 | 属性から判断へ | 入門出口の復習→設計判断。用語の地図の手前（少数問） |
| 関係 | 関係の種類 | 対称・推移・逆など判断へ拡張 |
| 制約 | 制約 | 必須・一意・開世界の緊張など |
| （入門に薄い） | 推論の期待値／タクソノミ対比／ナレッジグラフ／LLM時代の役割／運用・版管理 | **入門クリア後の本丸** |

学び順の位置: 入門「属性」章のあと → 基礎「属性から判断へ」（6問）→「用語の地図」。
