# エージェント業務プロンプト 変更提案と反映履歴

プロンプト本文の正本は docs/AGENT_PROMPT.md。このファイルはその差分の申請書と台帳。
2026-09-29 に社長から「プロンプトを変更したくなったら書類にまとめておいてくれれば変えておく」
との指示を受けて作成。以後ずっとこの経路で更新する。

## 手順(エージェント側)

1. この docs/AGENT_PROMPT_PROPOSALS.md に提案を append で足す。
   書くのは4つだけ: 何を変えるか / なぜ(観測した事実) / 置換前の文面 / 置換後の文面。
2. docs/AGENT_PROMPT.md の該当箇所を PATCH_V1 の置換で直す。
   このとき本文の末尾に何も足さない。社長は「ここから本文」以降を末尾までコピーするので、
   本文の後ろに付録を置くと一緒に貼られてしまう。追記したい情報は本文の中の該当節に入れる。
3. Slack に1行で伝える。「プロンプトの更新提案: (要点)。docs/AGENT_PROMPT.md を貼り替えてください」
4. 社長が貼り替えたと分かったら、AGENT_PROMPT.md 冒頭の反映状況と版を書き換え、
   この台帳の該当提案に反映日を入れる。

## 手順(社長側)

docs/AGENT_PROMPT.md を開き、「ここから本文」の行より下を末尾までコピーして、
スケジュールタスクのプロンプト欄に貼り替える。それだけで完了。
貼り替えたらSlackに「プロンプト反映した」と1行ください。台帳に反映日を書きます。

## 注意: 反映されるまではファイルは効かない

このリポジトリを直しても、あなた(次の私)に実際に渡される本文は変わらない。
渡された本文と docs/AGENT_PROMPT.md が食い違っていたら、
渡された本文が現に効いているほうで、ファイル側は提案。勝手に「もう変わっている」と思わないこと。

### 提案001: 出社したら前便のパッチが main に入ったか確かめる(未反映)

何を変えるか: 「出社したら、まず記憶を取り戻す」に4番目として、
前便で出したパッチが main に入ったかを git log で確かめる、を足す。

なぜ: 2026-09-29 11:49 JST 時点で、今日出した 07:56 / 08:56 / 08:57 / 10:01-10:03 / 10:58-10:59 の
パッチは main に1件も入っていない(auto: で始まる最後のコミットは 9/29 07:00 JST)。
9/24-9/28 の5日間の停止も、外から見えるのは同じ「無音」だった。
無音を早く見つける唯一の計器が git log なので、記憶を取り戻す手順に入れたい。
入れなくても毎回やればよいが、まっさらで起動する以上、手順に書いていないことは抜ける。

置換前: 3. Slackの直近30件 — buz-dojo-agent (channel_id: C0C34F5M1QV) を読む。
置換後: 同じ行のあとに 4. として「前便のパッチが main に入ったかを git log --oneline -10 で確かめる。
auto: で始まるコミットが前便の分まで来ていなければ、ブリッジが止まっているか全件破棄されている。
その場合はSlackのブリッジ発言を探し、無ければ止まっていると判断する」を足す。
