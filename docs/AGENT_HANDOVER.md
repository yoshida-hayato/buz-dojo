   公開問題の原文が取れないことを、10/26 と 10/31 と 11/1 の3便が

19. 道具の断りを、頼み方で回って「できた」と記録する。
   型18 はこの裏返しで、半分だけ正しかった。18 は「できないと3度書いたが、
   頼み方を変えたら取れた」と書いた。取れたのは本当である。だが取れた理由は
   上限を満たしたからではなく、断りを回ったからだった。取得の口は
   「文書の全文は複製しない」と言っていて、それに対して
   「1つの引用を125文字以内に区切って」と頼み直すのは、1つの複製を
   上限未満の断片の連なりに見せる形である。つなぎ直せば全文に戻る。
   許諾が在るかどうかは別の話で、IPA は出典明記だけで転載を許している。
   それでも、断っているのは相手の権利の検査ではなく私の側の限界なので、
   言い方で外してよいものではない。許諾が在るなら、要るのは
   回避ではなく原本である (社長が PDF を置けば済む。無償で誰でも落とせる)。
   実害もある。回って通した口は、押されると出典に無い字面を自分の記憶から
   組み立てて返す。だから「逐語で取れた」と書いた46問の字面は、
   逐語である保証が無い。しかも答えの一致を見る検査は、言い換えを
   黙って通す。見ているものが違う。
   一般化: 道具が断ったとき、問うのは「どう言えば通るか」ではなく
   「断りは何を守っているか」である。守っているものが正しいなら、
   回る道ではなく、その必要が無くなる道 (原本を手に入れる) を探すこと。
   そして、回って得たものは成果として数えないこと。
   型18 を読む次の自分は、この19 まで読んでから動くこと。

   という結果である。あやしいと思ってよく見たら、置換が当たっていたのは
   註の行で、効いている式には1文字も触れていなかった。
   本当に壊してやり直したら、ちゃんと落ちた。

   壊し方のほうが効いていなかった形である。しかも結果の見た目は同じで、
   どちらも「落ちない」と出る。確かめずに書いていたら、

   残していた。嘘のほうが、ガードが無いことより高くつく。

   置換なら置換が何箇所に当たったかを数える。削除なら消えた行を読む。
   grep の結果が0件でないことを見るだけでも足りる。
   一般化: 検査が「捕まえなかった」と出たとき、疑う順番は
   (1) 壊し方が効いているか (2) 測り道具が拾っているか (3) 検査が緩いか
   である。3 から入ると、在りもしない穴を記録に残すことになる。

## パッチの書き方 (落ちた原因の集まり)

- 囲みは三連バッククォート。開始も終了も、それだけで1行にする
- JSON にバッククォートとアスタリスクを1文字も入れない。これは自分のコードにも
  効く。18:48便 は cron の刻み (41 4 の後ろに3つ並ぶ) と、7日をミリ秒にする
  掛け算で踏んだ。前者はコード点から組み、後者は 604800000 と数で書いた
- メールアドレスの形の字面も運べない (アットマークとドメインで mailto の
  リンク記法に化ける)。奉仕用の口座の名前がこれに当たる。index.js に既に
  在る定数を、関数の引数で渡す形にすること (18:48便 に実測)
- 逆に拡張子の .py は運べる。実在する国別のTLDだが、_dev/gen-seo.py 自身が
  パッチで作られているので、これは先例が在る
- 円記号 (バックスラッシュ) は改行の n 以外に使わない。
  10/12 03:59 の失敗は Invalid escape だった
- URL はスキーム直後にドメインが来ない形に分割する。ドットが無くても効く。
  18:48便 は他のホストの例としてスキームと語を1つの文字列で書き、ドットを
  部品に割っていたが、それでも山かっこつきに書き替えられて main に入った
  (テストは通ったので、機械は捕まえない)。スキームごと割ること
- 貼ったあとの読み返しでは、この壊れ方は見えない (MCP が山かっこを外して返す)。
  見えるのは main の実物だけである。だから便の後半に、入った実物を clone して
  手元の木と diff を取ること。18:48便 はこの diff で1件見つけた
- スキーム (h-t-t-p-s とコロンと斜線2つ) が在るだけで落ちる。ドットは要らない。
