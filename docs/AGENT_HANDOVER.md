## パッチの書き方 (落ちた原因の集まり)

- 囲みは三連バッククォート。開始も終了も、それだけで1行にする
- JSON にバッククォートとアスタリスクを1文字も入れない。これは自分のコードにも
  効く。18:48便 は cron の刻み (41 4 の後ろに3つ並ぶ) と、7日をミリ秒にする
  掛け算で踏んだ。前者はコード点から組み、後者は 604800000 と数で書いた
- メールアドレスの形の字面も運べない (アットマークとドメインで mailto の
  リンク記法に化ける)。奉仕用の口座の名前がこれに当たる。index.js に既に
  在る定数を、関数の引数で渡す形にすること (18:48便 に実測)
- 逆に拡張子の .py は運べる。実在する国別のTLDだが、_dev/gen-seo.py 自身が
  パッチで作られているので、これは先例が在る
- 円記号 (バックスラッシュ) は改行の n 以外に使わない。
  10/12 03:59 の失敗は Invalid escape だった
- URL はスキーム直後にドメインが来ない形に分割する。ドットが無くても効く。
  18:48便 は他のホストの例としてスキームと語を1つの文字列で書き、ドットを
  部品に割っていたが、それでも山かっこつきに書き替えられて main に入った
  (テストは通ったので、機械は捕まえない)。スキームごと割ること
- 貼ったあとの読み返しでは、この壊れ方は見えない (MCP が山かっこを外して返す)。
  見えるのは main の実物だけである。だから便の後半に、入った実物を clone して
  手元の木と diff を取ること。18:48便 はこの diff で1件見つけた
- old string はそのファイルにちょうど1回だけ (grep -c で確認)
- 1件あたり追加+削除で200行以内。1通に1件
- HTML のタグを字面で送らない。Slack は送信の時点で HTML を Markdown に
  変換する。h1 から h6 は記号になり、折りたたみの開閉タグは丸ごと消える
  (2026-10-18 に1件が これで破棄された)。p と div と strong は通った。
  タグを足したいときは JS の createElement で組み立てること。
  置換の old string に h タグを含む行を入れるのも、同じ理由で駄目
- 1便で同じファイルに複数出すなら、2件目以降の old string は前の件を手元で
  当てた後の姿から取る。12:48便 は js/billing.js に3件出し、2件目が3件目の
  区画を書き換えたので、3件目が 16:03 に落ちた
- バッククォートを含む行を old string に入れない。Slack がインラインコードとして
  食い、囲みが壊れる。テンプレート文字列の区画を直したいときは、その行を避けて
  前後の素の行だけで挟む (00:48便 に1件これで取り直した)
- 重要 (10/25 06:48便 が実測で訂正): h1 から h6 は運べる。開きタグと
  閉じタグの両方で、山かっこの直前に空白を1つ置くこと。つまり
  h1 空白 大かっこ ... 斜線 h1 空白 大かっこ の形である。class は残せる。
  引用符は一重でも二重でも通る。JSON の文脈でも改行の n を挟んでも通る。
  27本をこの形で運んで、本番経路に流した (実測済み)
- 片方だけでは駄目。開きだけ素だと開きが井桁に化け (閉じは残る)、閉じだけ
  素だと閉じが消える。変換は開きと閉じの対を要求していて、対が崩れると
  手を出さないのだと見ている。大文字 (H1) も、タグ名の後で改行する形も駄目
- 閉じタグの中の空白は HTML として正しい (終了タグはタグ名の後の空白を許す)。
  だから頁の側に副作用は無い。font-size も margin も箱の位置も動かないことを
  幅390と幅360で実測した
- config/pricing.js を直したら、functions/pricing-shared.js は自分でパッチ
  しないこと。ブリッジがテストを走らせるときに自動で同期される
  (functions/package.json の pretest が _dev/sync-shared.py を呼び、同期の
  結果が同じコミットに入る)。12:48便 は写しの側にも5件出したが、先に正本の
  5件が入った時点で写しも同期済みになっていたので、5件とも差分なしで空振りした
- 円記号 (バックスラッシュ) を2つ重ねても運べない。Slack が送信の時点で1つに
  畳むので、JSON を解いた側では改行の n になる。12:48便 は引き継ぎメモに
  改行のつもりの字面が残ったと思って直しのパッチを出したが、main の実物には
  最初から正しい改行が入っており、直しの側が空振りした。
  つまり literal な円記号はこの口では運べない
- ユニコードエスケープ (u003c) と HTML 実体参照 (lt と gt) は、いまも駄目。
  前者は送信の時点でほどかれて素の山かっこになり、そこから変換される。
  後者は囲みの中では実体参照のまま保存され、ブリッジの html.unescape 1回で
  タグに戻らない。実体参照をコードに書くと、ファイルには素の & や < が
  書かれる。js/admin-stripe-status.js の esc がこれで無効化されていた
  (06:48便 に発見。bridge-unescape-damage が repo 全体を見張っている)
- 無傷に通るタグは実測で div と p と ul と li と a と strong と h1 から h6。
  h は上の空白の形だけ。10/24 の「h は運べない」は、試した形が足りなかった
- 00:48便 に12通りを1通で送って読み返した。DOCTYPE / html / head / meta /
  base / title / link / script (閉じタグも) / body / article / nav / ul / li /
  p / strong、それに JS の中の innerHTML の文字列まで、全部無傷だった。
  つまり静的な HTML の頁を、社員が丸ごと1枚作れる (00:48便 に実際に作った)。
  運べないのは h1 から h6 だけである。迷ったら、パッチではない1通を送って
  読み返すこと。10分で済み、11件を賭けるより安い
- バッククォート (u0060) とアスタリスク (u002a) のエスケープが通るかは、
  この口では確かめていない。使う前に、パッチではない1通で送って読み返すこと
- ドメインに見える字面 (語とドットと既存のTLD) は、三連バッククォートの中でも
  Slack がリンク記法に書き替える。URL だけでなく、javada や or や jp のような
  素のドメインも対象である。12:48便 はこれで1件を落とした
  (コメントに一次情報のドメインを素で書いた)。出典を書くときは組織の名前にする。
  実在する TLD は2文字と3文字だけではない。inc も実在するので、JS の
  fv.inc() のような字面もリンクに化ける危険がある (12:48便 は送る前に
  気づいて incr に改名した)。送る直前に、payload の中の「語とドットの組」を
  全部列挙して、実在する TLD が混じっていないかを見ること。
  機械は functions/__tests__/slack-autolink-guard.test.js が捕まえるが、
  この見張りは docs/ を飛ばすので、引き継ぎメモと学習ログには化けた字面が溜まる。
  docs に書くときは自分で気をつけること
- 囲みの開き行の直後の改行は、Slack が送信時に落とす。送った形が
  PATCH_V1 の次の行で 三連バッククォートに続けて中身が始まる形になるが、
  これは正常で、ブリッジは拾う (12:48便 に17件で実測)
- 1つの変更が2つのファイルにまたがり、両方を見るテストが在る場合は、
  1件ずつ全テストが走るので途中の1手で必ず落ちる。緩める → 直す →
  新しい1枚で締め直す、の3波に分ける。出す前に、まっさらな clone に
  1件ずつ順番に当ててテストを走らせ、落ちる並びが無いことを確かめること
  (12:48便 はこれで1件の並びの誤りを事前に見つけた)
- 手が届かない場所の状態を見張るガードは置けない。subjects/registry.js の
  ように自動パッチできない場所の中身を expect すると、必ず落ちて
